# 业务组合规则

超级管理员进入“防广告规则 → 管理业务规则”，可以维护原有的明确业务招揽、短语删除、昵称营销、群内广告和两组聊天排除规则。识别规则支持新增、修改、停用、移除和调整检查顺序，可以编辑词组及正则、全部/任意/取反组合、匹配范围、公共条件和命中说明。群内广告仍受原有 advertising_ban 开关控制；聊天规则只能排除聊天，不能用来处罚群成员。

“公共条件与豁免”维护举报、提问、引用、劝阻及直接招揽之间的关系。“文本处理”维护字符转换、引用移除、分句和去除干扰字符等步骤。词表、例外、组合和转换表均保存在数据库的 SharedPolicy.business_rules；Python 只执行通用操作。条件的引用、字段类型、表达式及循环依赖会在预览和保存时检查，错误草稿不会写入数据库。

编辑后可以同时输入正文、昵称、转发来源标题或联系人，比较当前配置与草稿的命中和处置。保存需要读取时的版本，避免旧页面覆盖别人已经保存的修改；失败时草稿保留，重复请求不会重复落库。保存影响所有群，现有群级功能开关、白名单及管理员豁免继续有效。联系人广告筛选仍作为“是否按联系人策略处理”的证据，联系人本身的处置继续遵循原有群设置。

规则动作可选仅删除、删除并永久禁言、删除并永久封禁；聊天规则只能选择排除聊天。处置不会依赖管理员手写的命中说明：封禁说明会保留既有封禁类别，改为删除或禁言时会消除旧封禁类别，避免 JSON 保存后被说明文字误升级。等待执行的处罚、异步评估结果、归档预览、聊天输入和输出检查都使用业务配置，配置发生变化后会重新核实。

管理接口为 GET/PUT `/api/settings/business-policy`，PUT 使用 `If-Match` 版本和 `request_id`；POST `/api/settings/business-policy/preview` 比较草稿与当前配置。接口沿用后台的登录、超级管理员和 CSRF 检查，返回结构化结果，外部工具可以直接调用。

0026 数据库迁移从 `src/purrai/assets/business_rules.v1.json` 初始化独立的配置副本，不覆盖现有词库、学习规则、群设置或功能开关。初始化后不再合并种子；所有规则停用或清空后也不会恢复默认规则。尚无 SharedPolicy 记录的首次安装，在首次保存时使用同一份初始化数据。独立 Python 匹配函数未传入数据库 RuleSet 时保留安装默认值，便于离线调用；实际业务入口均显式加载数据库配置。

迁移前从既有样本及系统性变体记录了 5,461 组结果，覆盖六组匹配、举报豁免、昵称、来源标题及聊天直接提问，保存在 `tests/fixtures/legacy_business_behaviors.json`。`tests/test_business_rules.py` 同时验证任意替换词的管理生命周期、可编辑转换和豁免、三种真实处置及排队处罚取消；迁移测试验证旧数据库升级和已编辑配置不被重新初始化。

合并 GitHub main 的既有提交时，另将远程的资源引流、主页社群及营销昵称判断接入相同数据模型，保留链接证据、引用与举报豁免。初始化数据因此共 41 条规则、6 个公共条件和 15 套文本处理。5,461 组历史对照继续验证原 28 条规则的数据版本，新增远程行为由 profile、wallet、guest-resource 相关回归验证。
