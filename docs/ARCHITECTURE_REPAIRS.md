# 2026-10-30 架构问题修复

本次对应检查报告中的 A01–A09，保留单进程 Python、SQLite 与 Vue 的部署方式。没有添加新依赖，没有部署到服务器，也没有操作真实 Telegram 群或模型接口。开始工作时已有的未提交修改继续保留。

| 问题 | 修复结果 | 主要验证 |
| --- | --- | --- |
| A01 排队后停用规则仍永久禁言 | 任务保存原始命中证据，在真正限制成员前重新检查当前有效规则；已被 Telegram 接受的限制先恢复回执，避免重复限制或丢失归属 | 正文、昵称、组合规则的停用、改词、降级与查询中变更；通用规则变更；已接受但丢失回执 |
| A02 同步计算阻塞全服务 | 消息、入群昵称和指纹评估在工作线程及写事务之外执行，写入前比较配置快照；文本与规则匹配使用有界缓存，拼音按音节边界直接匹配 | 故意阻塞规则计算时，事件循环和无关写入仍能继续；计算期间改规则后丢弃旧结果 |
| A03 旧表单覆盖新决定 | 规则与白名单返回内容版本，Web 和 Bot 带版本提交；版本也包含是否继承通用规则，显示内容相同的继承变化同样产生冲突 | 旧表单不能重新启用规则、恢复豁免、移除已变更白名单；旧 Bot 输入不能覆盖新编辑；冲突保留网页草稿 |
| A04 新增规则重试重复创建 | 管理写入在标签页会话存储中保存原编号、内容、版本和目标；后端将编号绑定操作意图，再次确认返回同一结果 | 同一请求只产生一条规则；同编号不同内容返回冲突；浏览器丢失回执、刷新后沿用原请求确认 |
| A05 轮询耗尽共享配额 | 登录、账号读取、账号写入和匿名请求分开计数，健康与静态资源独立；隐藏页面暂停查询，429 遵守 Retry-After 并退避；Nginx 模板同步调整 | 读取额度用尽仍可写入和检查健康；前端等待期间不继续请求；已有批量回执与浏览器场景 |
| A06 拒绝申请回执丢失后卡住 | 请求发送前保存意图、申请批次和冷却；未知结果结束该次本地验证并显示明确说明，停止重复拒绝；新申请仍由新批次判断 | 接受拒绝后丢失回执只发送一次，本地验证不再卡在处理中，保留冷却和未确认记录 |
| A07 工作任务退出不恢复 | 运行管理层监督并退避重启常驻任务，分别保存任务与轮询错误；系统接口返回各任务状态，恢复等待时就绪检查失败 | 一次启动异常后恢复，停止时不重启，成功轮询不能抹去任务故障，原有启动健康检查 |
| A08 登录被无关群查询拖住 | 身份接口只确认登录身份；群发现有总体期限，优先已知群并接续未完成扫描，明确返回部分失败；具体群操作继续核实当前权限 | 45 群中仅一个正常时仍在时限内返回；身份接口零次群权限查询；后来撤销权限不能借群列表结果提交操作 |
| A09 临时记录无限积累 | 0023 增加交互到期和收件完成时间，小批整理过期数据，有积压时继续处理；归档容量只计算归档自身数据 | 保留未完成、失败输入和业务历史；迁移给旧按钮完整过渡窗口；临时或其他表膨胀不挤占归档额度 |

核心回归在 `tests/test_architecture_repairs.py`，迁移回归在 `tests/test_temporary_state_migration.py`。前端新增 `mutationRequests.test.ts`，并在 `admin.spec.ts` 中覆盖丢失回执、冲突草稿和部分群失败。已有测试中与新契约矛盾的断言已更新，鉴权、错误结果与状态断言继续保留。

本轮还核对了修复之间的边界：规则评估期间不持有数据库写锁；权限发现的结果不代替实际管理操作的当前权限；拒绝申请的未知结果不冒充确认成功；到期整理不清理违规、操作审计或消息归档。近期乱序消息仍可记录，已过保留期的旧输入不因收件回执清理而重新生效。

升级需要停服并执行 `purrai init-db` 到 0023，然后启动与新前端构建配套的后端。迁移包含既有数据库的升级前备份流程。HTTP 请求头、部分群状态、到期窗口和归档计量说明见 [运维说明](OPERATIONS.md)。本地验证的结果记录在仓库 `data/diagnostics/20261030-architecture-review/`，最终验收记录见 [VALIDATION.md](../VALIDATION.md)。
