# 聊天系统整体复核（2026-10-22）

本报告记录发布前的本地工作区复核，包括上一轮的修改。覆盖入站审核、触发判断、连续消息、上下文、单次模型请求、额度、文字及贴纸发送、限流重试、重启和设置接口。复核阶段没有访问生产服务器，没有更换模型、增加分类模型或改变聊天人设。

## 结论

保留当前单次模型调用结构。已经可以由程序确定的条件由程序处理，模型只看有效文字，并在一次请求中决定是否回复、回复正文和贴纸。主要缺陷集中在消息合并和状态衔接；本轮没有继续修改提示词，仍是 954 字符，完整内容见 [提示词审阅](CHAT_PROMPT_REVIEW.md)。

当前流程为：先完成群审核 → 排除系统流量和功能口令 → 等同一用户的连续消息发完 10 秒 → 排除图片消息组、失效消息和引用 → 请求一次模型 → 检查当前设置、上下文和输出 → 引用原消息发送 → 保存已确认的发送回执。

## 已复现并修正的问题

| 原行为及影响 | 当前处理 |
| --- | --- |
| 每条消息各等 10 秒。用户第 6 秒补充一句，第一句到第 10 秒就可能先被回答。 | 同一用户在同一群及子话题内，相邻消息间隔不超过 10 秒算一组；后续补充会延后这组尚未处理的请求，等最后一句后约 10 秒再检查。 |
| 两个人同时点名机器人，整个队列只选最后一个问题，其他问题被标成合并。被删的最后一条也会连带取消前面的正常提问。 | 同一用户的一组发言可以合并，不同用户的明确提问分别保留。先逐条剔除失效候选，再选择回复目标。 |
| 只检查图片前后各 10 秒。文字、文字、图片每条相隔 8 秒时，第一条距图片 16 秒，仍可能被回答。 | 图片判断与消息合并使用同一个按时间连续分组的函数，整组含图片就保持安静；独立成员及子话题互不影响。 |
| 生成答案期间收到同一用户的补充，主动聊天关闭时可能没有入队；排队后又可能因为它早于机器人的回复而丢失。 | 同一组正在处理的请求可接收补充；通过上一次请求编号和同组关系确认续聊。别人、其他子话题以及明确回复第三人的消息不能借此进入对话。 |
| 续聊时间只判断“小于 90 秒”，负数也满足，早于机器人回复的无关消息可能被误判成续聊。 | 普通续聊需要位于机器人回复之后；只有能够关联到同组既有请求的排队补充才单独处理。 |
| “刚聊过”会绕过普通插话的广告静默检查。 | 未被直接询问的广告议论保持安静；同一用户明确问过广告问题后，正常追问可以继续，不会把“广告”整体变成禁词。贴纸不会清掉这段正常对话的状态。 |
| 开启了 `allow_sending_without_reply`，原消息已被别人删除时仍可能单独发出点评。 | 文字和贴纸均关闭该选项。Telegram 明确返回原消息不存在时取消发送，把缺失事实写回既有删除记录，使缓存与归档也能排除它；不会为记录这件事再执行一次删除。 |
| 文字发成功、贴纸被限流后，重试使用的是新整理的上下文，原答案依据的内容已经被删也可能继续发贴纸。 | 临时重试记录保留最初生成答案所用的上下文，重试仍校验它；正常新增聊天不导致重复生成或重发正文，原上下文失效就取消剩余发送。原消息不存在不会被误当成贴纸包坏了。 |

关闭原消息丢失时继续发送的选项，依据 [Telegram ReplyParameters 文档](https://core.telegram.org/bots/api#replyparameters)：开启它会允许在被引用消息找不到时继续发送。

## 保留的行为

被 @、叫昵称或回复时优先处理；正常短追问及其他成员接话仍可交给模型判断。主动参与讨论继续受间隔限制，模型可以选择不回应。同群的 Telegram 子话题及不同群各自维护上下文；模型请求和 Telegram 网络发送期间不持有数据库写锁。

保留上下文条数、字符数和有效期限制，以及既有每日额度、短时调用间隔、发送前输出检查、贴纸选择和去重。明确限流可以重试，发送结果不确定时不会为了追求成功而自动再发一遍。恢复、编辑和重复事件不会重新创造一条已完成的回复。

不增加语义话题识别、第二次模型审核、长期用户画像、向量库、Agent 编排或识图服务。群昵称、人格、模型参数、贴纸包及贴纸间隔未修改。新增的对话状态只有上次请求编号及是否正在正常讨论广告，均复用现有群话题状态。

## 实际限制

10 秒是调用模型前的等待，实际看到回复还需要模型和 Telegram 的处理时间。等待结束之后才补发的内容可能成为下一次续聊；已经成功发出的文字不会因为后来的补充被自动撤回。

外部删除没有同步记录时，程序无法事先准确重建全部历史状态。现在可以在引用发送时拦住“目标已不存在”的回复，并记录 Telegram 明确返回的缺失事实；普通广告识别仍可能受到模型判断影响。不会将发送错误、网络超时或其他不确定结果冒充为删除成功。

## 验证

新增复现场景先在旧实现上确认失败，再进行修正；测试使用独立临时数据库和模拟 Telegram、模型，没有向真实群发送测试消息。结果记录在 [验证记录](../VALIDATION.md)。复核阶段未调用付费模型；后续推送和服务器更新结果以实际部署记录为准。
