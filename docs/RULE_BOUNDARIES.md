# 关键词和规则的修改边界

2026-11-14 按用户“发按钮就删除并永久封禁”的明确要求，补充可配置的 `inline_buttons_ban` 消息结构检查，读取 Telegram 本条消息的 `reply_markup.inline_keyboard`，不读取按钮文案作为匹配条件。现有 Rule 与业务表达式只接收正文、昵称、来源标题等输入，不能表达这个结构事实；该能力复用既有删除和永久封禁动作。检查记录仅调整 `admin_labels.BOOLEANS` 新开关的界面标签，并增加 `advertising_constants.BUTTON_REASON` 处置原因标记；两处均不承载业务词条，不用于识别用户文字。没有修改检查算法、三个适配入口摘要或安装种子；测试用任意按钮文字、回调和复制按钮验证。

2026-11-13 按用户“独立关键词加 AI、统一谐音和加点规避”的要求，`chat_input.py` 的链接判断改为调用 `chat_links.input_links`，并传递当前数据库规则；此处只调整该适配入口的 AST 摘要，没有新增匹配内容豁免或修改安装种子。通用处理仅将命中已启用 AI 关键词、仅含汉字和点、且没有 Telegram URL 证据的疑似域名作为关键词文本；真实链接证据仍优先，停用或换词立即改变结果。实现不包含业务词，字词仍全部来自 Rule / SharedPolicy；`text_matching.py` 同时保留中英混合词的字母。测试以可替换词验证，并覆盖实际 URL、隐藏链接、规则修改与停用。

2026-11-13 的 AI 确认关键词处罚增加通用处置 `ai_confirmed_mute`，具体词仍从 Rule / SharedPolicy 读取。边界清单只调整 `admin_labels.py` 中 `OPERATIONS` 的原有一项：操作名称由“AI最近3天累计3次广告永久禁言”改为“AI广告永久禁言”，以涵盖累计处罚和关键词加 AI 确认两种来源。该字典只给操作记录显示名称，不匹配消息正文；对应摘要仅随这一项已审查的界面变更更新，未改变检查逻辑、业务种子或适配入口。

2026-11-11 的关键词自动回复功能另外使用 `AutoReply` 数据表，触发词和回复正文均由管理 API、Bot 面板和网页保存，不向防广告引擎或安装种子添加样例。本次逐项核准了两处界面常量误报：`admin_labels.py` 的 `OPERATIONS` 仅新增“关键词自动回复”和“修改自动回复规则”两个操作名称；`bot_auto_reply_panels.py` 的 `AutoReplyPanels.route` 字典仅为关键词、回复文字、优先级和冷却秒数的输入提示。两处均不参与消息内容匹配，因此只替换原操作名称记录并添加这一项提示记录，保留检查范围、旧记录、三个适配入口和种子保护；摘要只对应这两项已审查的界面变更。

简单关键词通过现有 Rule / SharedPolicy 维护，原来三份旧业务模式已按本次明确授权迁入 SharedPolicy.business_rules。后台“防广告规则 → 管理业务规则”可编辑 41 条规则、6 个公共条件和 15 套文本处理，包括具体词组、正则、组合、例外、顺序和处置。使用方法见 [BUSINESS_RULES.md](BUSINESS_RULES.md)。日常增删词属于数据操作，不能修改 Python、前端、迁移或安装种子来追加案例。

仓库根的 [AGENTS.md](../AGENTS.md) 将这条要求作为以后进入项目的 Agent 约束。交付前运行 `python scripts/check_rule_boundaries.py`；pytest 中的 `tests/test_rule_boundaries.py` 也执行相同检查。命令只读且不提供 `--write`，不能通过刷新基线或跳过测试解决新业务硬编码。

检查器扫描 `src/purrai` 下的 Python 文件，检查新增或改动的字符串比较、匹配调用和词表常量，记录文件、函数、行号和内容。数据库值作为匹配输入、测试样本和通用字符处理不会被当成新关键词。复制已有字面量判断增加一次使用也会触发检查。行号不参与身份比较，正常换行不会要求刷新基线。

本次基于迁移授权从清单中移除了 71 项旧匹配表达式，合并远程后共有 117 个候选表达式包含协议标记及界面常量，不是广告词数量。没有添加新的词组豁免。格式 2 基线保护迁移后的三个适配入口和安装种子摘要，三个文件已经不再包含业务模式；适配入口的冻结不能替代这次实际的数据迁移。数据种子只用于初始化，后台编辑不会修改仓库文件，因而不会触发种子保护。

原有四种封禁原因类别标记统一放到 `advertising_constants.py`，让规则引擎与旧适配入口保持单向依赖。这四项只标识处置类别，不匹配正文或昵称，也不包含广告关键词；本次检查清单只对其位置迁移作了对应调整。

基线本身另有摘要校验。不得同时修改基线与摘要来放行新增业务词；通用能力调整或后续明确授权的迁移必须审查实际差异。保留对三份适配入口的整体语法树检查，是为了防止业务判断重新藏回去。安装种子摘要防止把新增案例换成修改默认 JSON 绕过后台。

静态检查不是语义证明：前端、任意新迁移或间接构造不在此次 Python 扫描的完整覆盖范围内，仍须遵守项目约束并检查实际差异。独立命令与正常 pytest 是实际检查入口，没有安装额外 Git 钩子或创建 CI 服务。业务等价对照、任意规则生命周期和数据库迁移回归见相应测试，不能仅凭静态检查声称功能正确。

合并远程 main 时，仅接纳双方已有的操作文案、原因类别、链接排除和低信息量占位标记，不放行正文广告词判断；检查器逐项比对双方 Git 快照中的字面量来源。远程广告模式进入可编辑数据后，相应更新了安装种子和适配入口摘要，以保存两边功能。
