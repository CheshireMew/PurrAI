# 独立广告审核与样本复用

群消息先经过现有规则，再记录持久化审核任务。进入聊天调度的消息由同一次模型请求返回广告判断和聊天回复，广告结果只执行处置并停止回复。昵称、简介和正文一起发送，AI 可以用自己的话说明理由。没有聊天请求的消息继续独立审核，默认每批最多 12 条。各条消息分别记录状态、模型理由、版本及样本来源，漏答、连接失败和进程中断保留恢复入口。

积分设置支持逐级豁免：本人在本群的历史最高积分达到 50 后解除新人发图、链接、提及和转发限制，达到 100 后跳过广告样本匹配和模型审核，需要聊天时只进行对话。历史签到、聊天及其他已入账积分均计入，不再额外要求聊天活跃天数；消费或扣分后保留资格。管理员仍可修改门槛、停用自动豁免或取消指定成员的自动豁免。资格按本群与积分入账时绑定的 Telegram ID 核对，改绑不会直接转移原身份的历史资格。

## 结构化消息内容

审核统一读取本条消息中实际提交的文字和链接：普通正文、媒体说明、核对清单标题和条目、投票题目/选项/说明及附带媒体信息、地点名称和地址、文件名、音频标题和表演者、游戏和账单说明，以及富文本的段落、格式化文字、列表、表格、折叠摘要、媒体说明、按钮文案、复制内容和链接。清单、投票、游戏、富文本及按钮中的实体分别按各自文字的 UTF-16 偏移读取，表情标识也交给现有表情包规则检查。格式依据当前安装的 SDK 和 [Telegram Bot API](https://core.telegram.org/bots/api#available-types)，字段本身不构成违规，不新增广告词或专用处罚。

`message_parts.py` 负责读取本条消息的内容，规则、外群链接检查、样本、AI 审核、归档展示和搜索共用这份结果。编辑会使旧审核版本失效，处罚前继续复核最新内容与规则。普通回复、置顶、引用、转发来源资料、外部回复和服务消息中的原消息快照不被递归当成当前发送者的正文；AI 可以按原有方式将引用作为独立上下文。

清单新增任务、投票新增选项的服务通知只审核添加者实际新增的文字。命中后按现有规则处理添加者，并清理包含新增广告的原清单或投票，不处罚原作者；若已收到原消息的后续修改，执行前核对新增内容是否仍然存在。关闭完整归档时，只为这类编辑保留最长 47 小时的复核资料，过期后沿用现有清理机制。新版本不会主动重扫和处罚历史归档。

归档保留原始结构及编辑版本，页面和 Bot 可直接查看提取后的文字；关键词搜索也覆盖后来被编辑掉的结构化正文。这里读取的是 API 提供的文字、链接和表情标识，没有增加下载图片、视频或文件、OCR、语音转写或解析文件正文。只有像素中的字或与表情替代字符不同的图形文字仍不能保证识别，但同一消息里实际存在的邀请链接及已配置的表情包规则会照常检查。

## 本地匹配

正文能独立证明广告的人工或 AI 判定可成为样本，同群不同账号可复用。相似度采用字符序列覆盖率和字符二元组重合度，借鉴 Glean 的字符比较方式，不引入新闻实体和事实冲突规则。先统一字符格式、移除不可见格式字符，规范化数字、网址和联系方式，再比较。默认阈值 0.90、至少 14 个有效字符、至少覆盖原样本的 55%。这些设置和处置动作均存于数据库，可通过后台修改。

分数不是广告概率。近似改写即使分数高，新增或替换文字仍可能改变含义，因此交由 AI；单纯规范化差异、变量替换和保留足够正文的缩短副本可直接匹配。引用、转发、带引用格式和依赖上下文的消息不直接处置。默认命中删除消息，可配置为删除并永久禁言。本地命中不会增加 AI 独立确认次数，也不会生成新样本。

## 管理

入口为“本群广告规则 → 广告样本与审核”，可添加、搜索、编辑、停用样本，试算匹配，查看每条消息的审核记录并重试失败项。样本修改、停用、来源纠错、原消息编辑及策略版本变化，均在实际处置前重新核对。已完成的 Telegram 删除无法撤回；停用样本阻止后续匹配及尚未执行的旧处置。

“导入历史判定”先展示候选数量，确认后从现有 AI 违规记录及历史 AI 计数记录导入，排除已纠错的记录。旧记录无法证明是正文还是昵称导致判定，因此先保留为待复核样本，后台空闲时批量复核正文适用范围；复核不处罚历史消息。无需修改安装种子或代码词表。

管理 API 位于 `/api/groups/{group_id}/advertisement-samples`、`advertisement-settings` 和 `advertisement-reviews`。写入沿用现有鉴权、幂等键、版本检查和审计；样本不提供物理删除入口，可停用。

## 运行边界

审核共用现有模型连接及全局、群每日 AI 额度。独立审核不受聊天的用户间隔限制，聊天调度的合并请求沿用聊天间隔。额度耗尽时显示待审及原因，本地规则和已有样本继续工作。每条消息只交给一个请求流程，聊天任务未执行完成时可恢复到独立审核；回复发送失败时复用已经取得的模型结果。已判广告和其他尚未审核的消息不进入普通聊天上下文。

0032 迁移只新增审核策略、样本、逐消息审核表，不自动修改线上词库、导入历史数据或追罚历史成员。本地验证使用模拟模型与 Telegram，不代表真实模型准确率或线上删帖延迟；需要明确部署后才会在线生效。

## 规则边界核对

0033 将剩余功能口令、可学习口令、其他机器人口令、机器人输出限制、电话提示词和短链接服务名单共 19 项迁入 `SharedPolicy.business_rules.recognition`。入口为“防广告规则 → 管理业务规则 → 口令与目标识别”，沿用版本检查、审计和当前/草稿比较。各类支持添加、修改、停用和清空；旧的学习记录也受最新可学习口令规则约束。空列表不恢复安装默认值。电话提示词负责提取目标，短链接名单决定记录完整链接还是域名，二者本身都不构成广告证据。机器人输出限制仅阻止机器人发送，不处罚成员。

原有群口令忽略列表、状态表情黑名单、聊天贴纸和反诈贴纸的初始值改从 `assets/group_defaults.v1.json` 读取，现有后台编辑和空列表语义不变。`assets/recognition_policy.v1.json` 仅供 0033 和首次安装，两份新种子纳入摘要保护。此次从冻结清单撤销六处已迁走的业务表达式豁免，仅精确登记六处配置分区字段误报；未改变原有扫描判断或旧广告种子。剩余记录主要是结果标签、界面文字及协议/字符格式，静态扫描仍不能证明所有间接硬编码均已检出。

此前独立广告审核登记的四处非业务词误报仍保留：`advertisement_admin.py` 的历史判定结果标签；`advertisement_similarity.py` 的通用网址格式；`chat_model.py` 从 `reply` 移至 `completion` 的输出长度协议字段和 HTTP 错误提示。它们不承载广告词条；原三份规则适配入口和旧广告安装种子保持原样。

## 0034 显式处置与提醒设置

“群设置／通用设置 → 审核与提醒”管理群内提醒保留秒数、AI 广告累计窗口与次数、累计后的处置、刷屏禁言时间、新成员发图观察天数、学习目标的默认处置、账号聊天冷却、口令学习窗口与人数、开场最短字数、纯数字开场及重复聊天窗口。原有行为作为初始值保留，群内处罚通知与群内操作结果默认发送约 30 秒后删除。私聊回执、普通聊天回复和未结束的验证题目不受该提醒时限影响。清理任务持久化，重启后继续；修改时限影响后续提醒，迁移会把旧待清理任务调整到保存的时限。

“管理业务规则”可编辑每条规则的账号冷却开关和共用 AI 审核标准。说明文字不再决定冷却；任意斜杠或下划线不再自动豁免审核，功能口令由后台识别数据定义。独立审核、历史样本复核和聊天兼容审核读取同一份准则；准则在模型请求期间变化时旧判定不执行处罚。输出格式仍由程序约束。

普通规则编辑支持昵称命中处置与推广目标处置。0034 将旧目标规则显式设为原来实际执行的封禁，将昵称规则设为原来实际执行的永久禁言；后续可改为只删、永久禁言或永久封禁。自动学习不再为已有本群目标生成更重的全局副本。规则筛选保留业务配置，清空识别列表不会回退默认值。已排队的规则处置会复核最新设置与消息，引用证据不再被同一版本的精简归档覆盖。

`business_rules.v2.json` 只新增原有 AI 准则与显式冷却标志，旧 41 条识别内容未增加；0034 不覆盖已保存的识别内容、启停或空列表，重复升级不重置管理员后来修改的处置。静态检查只精确登记 AI 准则字段存在性检查和两处显示标签更新，并保护新增种子摘要，未放宽扫描逻辑。动态回归覆盖管理保存、实际消息处理、待执行处罚、重启清理和迁移；这些验证不能证明其他间接写法不存在。旧结果前缀的存储兼容、Telegram 协议格式以及聊天上下文的 120 秒延续判断、6 小时缓存边界仍在代码中，未在本次改动中统一改成后台字段。

高收益招揽必须同时有招揽意图与实际引流目标；仅谈收入、盈亏或回答收益问题，没有目标时不判广告，也不能猜测未提供的联系方式或项目。具体准则保存在 `SharedPolicy.business_rules.ai_review_instructions`，独立审核与聊天合并审核读取同一份配置。公开通用准则同步在 `assets/public_moderation.json`；已有实例仍需通过管理入口更新已保存的准则，不在启动时覆盖。

大量自定义表情拼接广告不依赖表情包预先入黑名单，也不依赖识别图片中的字。公开配置的 `message_structure` 规则组默认要求单条消息至少 20 个自定义表情、占本条非空白正文至少 80%，命中后删除并永久封禁，并自动将本条实际使用的表情包加入通用拦截名单。数量、比例、处置和是否学习均在后台业务规则中维护；普通 Unicode 表情、引用和回复中的表情不计入数量，管理员与免自动处罚白名单仍豁免。自动学习保留来源消息和违规记录，沿用误判纠正入口撤销；已有禁用项及本群覆盖不被自动重启或加重。后续只发一枚已列入名单的表情也按该条规则处理。
